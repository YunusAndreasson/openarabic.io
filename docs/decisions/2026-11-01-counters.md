# Page views and store taps, 2026-11-01

Plan tasks 3.0 and 3.3. Store taps per page view, by page type, first-party, with no cookie and no script. Stored in Workers Analytics Engine, dataset `openarabic_site_counts`.

| What | How | Stored |
|---|---|---|
| Page view | A 1×1 image, `/v?p=<type>`, on every page, `no-store` | `view`, page type, and the platform's timestamp |
| Store tap | The Worker on `/download-app?to=&from=` | `tap`, store, surface, and the platform's timestamp |

Never an IP, user agent, word, slug or country. `HEAD` and known crawlers by user agent aren't counted.

## Prototype, measured 2026-11-01

`scripts/check-counters.mjs`, on a local build, counting the requests each browser made.

| Case | Chromium | Zen |
|---|---:|---:|
| First visit, cold | 1 | 1 |
| Reload | 1 | 1 |
| Second page | 1 | 1 |
| Back, then forward | 1 each | **0 each** |
| Images off, every case | **0** | **0** |

**Verdict: use, with a warning, wherever the number is reported.** It counts page loads. It misses visitors with images off, and returns through the back-forward cache, which is why Zen shows 0 there. So views run low and taps per view run high, by an unknown amount. A browser's prefetch could count a view that nobody saw, and that wasn't tested. Never call it visits.

**Tap signal, by reading the code, not measured:** a double tap counts twice. Link previews that follow a link are dropped only if their user agent looks like a bot.

**Dropped: the story's other signals** (word opened, control pressed, came near the last screen), from `docs/site-plan.md` `Concept A's risk`. They were designed for the page the owner rejected, and the rebuilt home page would need its own design. Nothing was built for them.
